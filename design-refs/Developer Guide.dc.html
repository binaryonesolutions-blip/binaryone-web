FIDELITY RULE — READ FIRST

The design files in this project are the single source of truth. Reproduce them exactly: same hex values, same font sizes to the half-pixel, same padding, same copy, same animation timings, same section order. Do not substitute a design-system component, do not round values to a Tailwind scale step, do not "improve" spacing, do not rewrite copy.

Where a value is not on Tailwind's default scale, use an arbitrary value — text-[15.5px] leading-[1.65] px-[26px] bg-[#0f766e]. Arbitrary values everywhere is the correct answer here.

2 · Canvas, grid & layout rhythm

DESIGN CANVAS

Fixed 1440px content column, margin:0 auto. Horizontal gutter is 64px on every page and every section without exception.

SECTION PADDING

Standard band 96px 64px. Hero 88px 64px 64px. Accent strips 64px. Final CTA 112px 64px. Footer 64px 64px 32px.

⚠ ONE DECISION THE DESIGN DOES NOT MAKE FOR YOU

Every design file ships a scaling shim that zooms the whole 1440px canvas to the viewport:

var r = (document.documentElement.clientWidth || window.innerWidth) / 1440;
if (r > 1.6) r = 1.6;  if (r < 0.15) r = 0.15;
document.documentElement.style.zoom = r;

That is a prototype device, not a responsive strategy. Ship it as-is for a guaranteed pixel-exact result, or ask the client to sign off a responsive breakdown before you write any breakpoint. Do not invent mobile layouts unilaterally — that is an alteration.

5 · Iconography & imagery

ICON RULE — NON-NEGOTIABLE

Every icon is an inline SVG on a 24×24 viewBox, stroked not filled: fill="none" stroke-width="1.6–2" stroke-linecap="round" stroke-linejoin="round". Stroke colour is #0f766e on light, currentColor or #38e0c4 on dark. Rendered sizes: 22px (feature tiles), 20px (nav dropdown), 18–19px (buttons), 14–17px (inline chips).

Do not swap in an icon library. Copy each <path d="…"> verbatim from the design files into an /components/icons module. Social icons (LinkedIn, X, Facebook) are the only filled icons — fill="currentColor", 20–22px.

Standard icon tile: 40×40px, radius 10px, background #eef4f3 (nav) · 44×44px, radius 12px, background rgba(15,118,110,0.10) (process cards) · 52px circle, #0f766e, white tick (success states).

9.1 · ENTERPRISE IT & AI DIAGNOSTIC (modal, 8 questions)

State: { diagOpen, diagStep, diagAnswers[], bookingSubmitted }. Opening resets all four.

Flow: one question per step, 3 options each (A/B/C, scores 1/2/3). Choosing pushes {score, category} and advances — there is no Next button. BACK pops the last answer. Body scroll resets to top on every transition. After the 8th answer the results view replaces the question view.

Categories & question count: infrastructure ×1 ("Cloud & IT Management"), security ×1 ("Cybersecurity Defense"), erp ×1 ("ERP Automation"), ai ×1 ("Agentic AI Readiness"), software ×1 ("Custom Software"), cx ×3 ("Customer Experience"). Max score 24.

Scoring: pct = round(sum / 24 × 100). Per-category meter = round(catScore / (3 × catQuestions) × 100), rendered in fixed order: Cloud & IT Management, Cybersecurity Defense, ERP Automation, Agentic AI Readiness, Custom Software, Customer Experience.
